# PHASE-M1.3-VALIDATION-AND-RECONCILIATION-CORE.md

## Executive Summary

This phase adds the functional core for Milestone 1. It validates the
LLM-shaped extraction input, validates optional actual payment evidence,
computes deterministic reconciliation decisions, and introduces a service that
persists the original snapshots with the repository from M1.2.

Expected outcome: backend tests can create reconciliation cases through the
service without HTTP routes and without a real LLM.

Assumptions:

- M1.2 has delivered database session, migration, model, and repository.
- `EXTRACTION_REVIEW_CONFIDENCE_THRESHOLD` is `0.80`.
- The LLM output shape is supplied by tests or callers, not generated by the
  backend in this milestone.

P_bottom_up: about 520 production LOC.
T_bottom_up: about 430 test LOC.

Required signatures:

```python
def validate_agreement_extraction_input(
    input: AgreementExtractionInputV1,
    confidence_threshold: float,
) -> ValidatedAgreementExtraction:
    """Validate LLM-shaped agreement evidence for the Base API.

    What: Normalizes the extraction payload accepted by Milestone 1.
    Why: The backend must trust only validated fields before making finance
        decisions.

    Args:
        input: LLM-shaped extraction payload from the API or tests.
        confidence_threshold: Threshold below which evidence text is required.

    Returns:
        ValidatedAgreementExtraction: Normalized agreement fields.

    Raises:
        ValueError: If required evidence, money, currency, payment type, or
            confidence values are invalid.
    """


def validate_actual_payment_input(
    input: ActualPaymentInputV1 | None,
) -> ValidatedActualPayment | None:
    """Validate optional payment evidence for the Base API.

    What: Normalizes manually supplied actual-payment data.
    Why: Milestone 1 compares one payment snapshot without a payment ledger.

    Args:
        input: Optional actual payment payload.

    Returns:
        ValidatedActualPayment | None: Normalized payment evidence, or None
        when no payment was supplied.
    """


def decide_base_reconciliation(
    extraction: ValidatedAgreementExtraction,
    actual_payment: ValidatedActualPayment | None,
    confidence_threshold: float,
) -> ReconciliationDecisionV1:
    """Compute the deterministic Base API reconciliation decision.

    What: Applies the Milestone 1 decision order to validated evidence.
    Why: LLM output must not decide final finance status.

    Args:
        extraction: Validated agreement evidence.
        actual_payment: Optional validated payment evidence.
        confidence_threshold: Configured review threshold from settings.

    Returns:
        ReconciliationDecisionV1: Status, amounts, difference, currency,
        reason, review flag, and confidence. Difference is always
        `paid_amount_minor - agreed_amount_minor` when both values exist.
    """
```

Schema contract:

```text
PaymentType values match API.md exactly.
JsonValue = str | int | float | bool | None | list[JsonValue] | dict[str, JsonValue].
AgreementExtractionInputV1 validates schema_version, money, currency,
  payment_type, confidence, review flag, review-prone evidence, and
  JSON-safe raw_llm_output.
ActualPaymentInputV1 accepts missing comparison fields but validates
  non-negative money and uppercase 3-letter currency when present.
ReconciliationCaseCreateRequestV1 is the service input.
ReconciliationCaseResponseV1 and ReconciliationCaseListItemV1 are service
  output models for the later API endpoint phase.
```

Decision pseudo code:

```text
if extraction.needs_human_review or extraction.confidence < confidence_threshold:
    return NEEDS_REVIEW
if extraction.agreed_amount_minor is None or extraction.currency is None:
    return NEEDS_REVIEW
if actual_payment is None:
    return PAYMENT_NOT_FOUND
if actual_payment.paid_amount_minor is None or actual_payment.currency is None:
    return NEEDS_REVIEW
if actual_payment.currency != extraction.currency:
    return NEEDS_REVIEW
difference = paid - agreed
if paid == agreed:
    return RECONCILED
if paid < agreed and payment_type in partial_like_types:
    return PARTIAL_PAYMENT
if paid < agreed:
    return UNDERPAID
return OVERPAID
```

Service contract:

```python
class BaseReconciliationCaseService:
    """Coordinate Base API validation, decisions, and persistence."""

    def __init__(
        self,
        repository: BaseReconciliationCaseRepository,
        confidence_threshold: float,
    ) -> None:
        """Store repository and threshold dependencies for service methods."""

    def create_case(
        self,
        input: ReconciliationCaseCreateRequestV1,
    ) -> ReconciliationCaseResponseV1:
        """Validate, decide, persist, and return one Base API case."""

    def list_cases(
        self,
        status: ReconciliationStatus | None,
        limit: int,
        offset: int,
    ) -> list[ReconciliationCaseListItemV1]:
        """Map stored repository cases to list-item response models."""

    def get_case(self, case_id: UUID) -> ReconciliationCaseResponseV1 | None:
        """Map one stored repository case to a detail response model."""
```

Mapping contract:

```text
request.extraction.model_dump(mode="json") -> extraction_snapshot
request.actual_payment.model_dump(mode="json") if present, else None -> actual_payment_snapshot
Validated decision -> M1.2 ReconciliationDecisionV1, including confidence
M1.2 BaseReconciliationCase -> ReconciliationCaseResponseV1/ListItemV1
```

### Refactor

- Keep decision logic free of database, FastAPI, settings, and environment
  reads.
- Keep service orchestration thin: validate, decide, persist, return.
- Do not add routers, LLM adapters, payment ledger matching, auth, or tenants.
